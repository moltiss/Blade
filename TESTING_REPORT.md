# Отчёт о тестировании Blade

**Практическая работа №6: «Тестирование разрабатываемого ПО»**  
Дата испытаний: 14.11.2026  
Репозиторий: [moltiss/Blade](https://github.com/moltiss/Blade)  
Ветка: `test/7-software-testing`

## 1. Объект тестирования

Blade — учебное клиент-серверное средство предварительного шифрования текста. Клиент на Python/PySide6 шифрует сообщения алгоритмом AES-256-GCM; сервер Flask обеспечивает регистрацию, авторизацию, хранение шифротекстов в SQLite, журналирование и распространение подписанных обновлений.

Объекты испытаний: `client/encryption.py`, `client/updater.py`, `server/app.py`, `server/auth.py`, `server/security_policy.py`, `server/database.py`, `server/logging_config.py`, `server/update_service.py`.

## 2. Методика

Использованы функциональные позитивные и негативные тесты, контроль краевых значений, генерация и мутация входных данных с Hypothesis, регрессионное тестирование и измерение покрытия исполняемых операторов исходного кода.

Среда: Windows 11, Python 3.14 (по трассировке), виртуальное окружение `.venv`. Инструменты: pytest, Hypothesis, pytest-cov. Точные версии установленных пакетов фиксируются в `requirements-dev.txt`; вывод версий и итоговый вывод pytest добавляются в приложение к настоящему отчёту.

Тестовые фикстуры используют изолированную SQLite-базу, конфигурацию и тестовые криптографические ключи. HTTP-запросы выполняются через тестовый клиент Flask. Для проверки сроков действия токенов и блокировки входа применяется подмена времени. Фаззинг выполняется без установки обновлений и без обращения к рабочей базе.

## 4. Найденные дефекты

**Некорректное UTF-8 имя файла в ZIP.** Связь с задачей фаззинга: [#10](https://github.com/moltiss/Blade/issues/10). Отдельный bug Issue необходимо сверить по фактическому номеру (ожидаемый номер: [#12](https://github.com/moltiss/Blade/issues/12)).

В `client/updater.py`, функция `validate_zip_package()`, открытие повреждённого архива приводило к `UnicodeDecodeError` внутри `zipfile.ZipFile._RealGetContents()`. Причина — недопустимый байт `0x80` в имени файла при установленном флаге UTF-8. Исключение не входило в обработчик ошибок ZIP.

Фактический результат: необработанное исключение на уровне валидатора. Ожидаемый результат: контролируемый отказ посредством `UpdateError`. Обход криптографической проверки не установлен.

Воспроизведение на локальном сохранённом входе:

```powershell
python fuzz/fuzz_blade.py --replay fuzz/crashes/crash-zip.json
```

Исправление: добавить `UnicodeDecodeError` в существующий обработчик исключений `validate_zip_package()` с преобразованием в `UpdateError`.

Регрессионный тест: `tests/test_regression_zip.py::test_zip_rejects_invalid_utf8_filename`. Тест создаёт небольшой ZIP, меняет флаг UTF-8 и байт имени в центральном каталоге; ожидает `UpdateError`. Отдельные результаты регрессионного теста и общего запуска необходимо подтвердить выводом pytest в приложении. Повторный фаззинг уже подтверждает отсутствие необработанных исключений в 8800 вызовах.

Crash-файлы не добавляются в Git. Изменение `client/updater.py` требует повторного подписания манифеста целостности при подготовке релиза.
